## Failure analysis (the actual calibration deliverable)

### ktoml-357 — harness-class: shell escaping blocks backslash-heavy Kotlin writes

The agent correctly diagnosed the root cause: `escapeBackslashes` in `SpecialCharacters.kt` has
bugs in the modulo-2 backslash-counting logic and quote/backslash ordering. The identified fix
required rewriting Kotlin string-literal escaping code that is itself backslash-dense. The
`box-sh` helper pipes code through `printf '%s' "$*" | ssh ... "cat > /tmp/_bc && docker exec
bash -lc ..."` — this double-shell-quoting cannot round-trip Kotlin source containing `\n`,
`\uXXXX`, `\\`, and `"..."` literals. The agent's patch included only a partial structural
change and an autogenerated `yarn.lock` (noise). The underlying fix was correct; the tooling
blocked application.

**Generalized invariant:** *The box-sh mechanism is not safe for arbitrary source code
containing backslash sequences or double-quoted string literals.*

**Proposed harness fix #3:** Replace inline piping in `box-sh` with a `scp`-based file
transfer: write the command to a temp file locally, `scp` it to the box, then `docker cp`
into the container and execute. No shell quoting of the payload at all.

### forwarddiff.jl-770 — model-wrong-implementation: overly broad catch-all dispatch

The agent correctly identified that 2-arg `valtype(::Type{T}, dual)` overloads were needed
and produced plausible Julia method signatures. However, it added an overly broad catch-all
`@inline valtype(::Type{T}, ::V) where {T,V} = V` alongside the Dual-specific methods.
In Julia, while `::Dual{T,V,N}` is more specific than `::V`, adding both creates method
ambiguity for non-Dual inputs and may shadow the specialized Dual-specific dispatch in
edge cases. The official grade returned 0/1 (the whole `ForwardDiff.jl` test module failed),
consistent with a dispatch error causing test-suite load failure or test failures.

Contributing harness factor: the offline container lacked the `StaticArrays` test dependency
(not pre-installed in the image), so the agent could not run the full gate to verify its
implementation. The agent reported 88 core tests passing internally but couldn't confirm the
StaticArrays-dependent tests. Golden-eval ran VALID (gold patch uses network to install deps;
the agent was offline).

**Generalized invariant:** *When adding new method overloads in Julia (or any multiple-dispatch
language), method specificity ordering must be verified — a broad fallback that overlaps
specific methods risks ambiguity or dispatch inversion.*

**Proposed harness fix #4 (environment):** During `warm_and_failbase`, explicitly run
`Pkg.instantiate()` (or equivalent) to ensure the full test-suite dep closure is installed
*before* cutting network. An offline warm that runs the test_cmd without instantiating
first will miss transitive test deps.

### mljbase.jl-1023 — model-incomplete-patch: missed 4 of N locations of same fix

The agent correctly identified the Julia 1.12 compatibility issue: `.name.mt.name` is no
longer valid; `.name.name` is the replacement. It fixed 3 locations (`nodes.jl:273`,
`operations.jl:111`, one in `show.jl`), producing 8/12 F2P. Four test cases remained
failing, implying 4 more locations with the same pattern were not found/fixed.

**Generalized invariant:** *When the root cause is a renamed/removed API field that
appears in N places, the fix must enumerate ALL occurrences before applying — a partial
grep-and-fix leaves the same error at unfound sites.*

**Failure class:** `model-incomplete-patch`. No harness contribution — the official eval
confirmed partial, so the container environment was functional.
